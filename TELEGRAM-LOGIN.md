# Первый вход через Telegram

## Сценарий

1. Новый пользователь открывает бота и отправляет `/start`.
2. Бот создаёт или находит его DEMO-профиль и выдаёт одноразовый ID вида `ABCD-EFGH` на 10 минут.
3. Пользователь вводит ID на стартовом экране приложения.
4. Edge Function обменивает одноразовый ID на случайный токен сессии. В базе хранится только SHA-256 токена.
5. После успешной привязки приложение показывает локальный четырёхзначный PIN-экран и затем открывает аккаунт.
6. Браузер сохраняет сессию локально. При следующем запуске приложение проверяет её, пропускает повторный запрос Telegram-ID и показывает PIN перед открытием того же профиля.

Четырёхзначный PIN — часть учебного интерфейса: он не отправляется на сервер и не сохраняется. Кнопка «Не пам’ятаю код для входу» очищает локальную Telegram-сессию и возвращает пользователя к вводу нового одноразового ID.

Пользовательский бот сохраняет имя, фамилию и `@username` из Telegram, а функция входа отмечает дату последнего успешного входа. Команда `/users`, просмотр Telegram ID и кнопки `0/1` находятся только в отдельном администраторском боте и ограничены `TELEGRAM_ADMIN_IDS`.

## Публикация

1. Выполнить `supabase/telegram-profile-auth.sql` в Supabase SQL Editor. Файл можно запускать повторно: он добавляет недостающие поля без удаления записей.
2. Повторно опубликовать пользовательский `telegram-visual-bot` из `supabase/functions/telegram-visual-bot/index.ts`.
3. Создать и опубликовать Edge Function `telegram-profile-auth` из одноимённой папки с выключенным Verify JWT.
4. Опубликовать обновлённый GitHub Pages. Новые секреты не нужны: используется существующий `NEXT_PUBLIC_SUPABASE_URL`.
5. Повторно регистрировать Telegram webhook не требуется, если URL `telegram-visual-bot` не менялся.

Администраторские команды публикуются отдельно по инструкции `TELEGRAM-BOT.md`.

Не публиковать `SUPABASE_SERVICE_ROLE_KEY` и не добавлять его в GitHub Pages.
