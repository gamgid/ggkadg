# Облік DEMO — GitHub Pages

Учебная версия с тестовыми данными. Не документ и не государственный сервис.
Репозиторий: gamgid/ggkadg. Публичный доступ без входа.

## Загрузка через браузер на Mac

1. В репозитории откройте Settings → Pages. В Build and deployment выберите Source → GitHub Actions.
2. Распакуйте архив `ggkadg-pages-source.zip`. Откройте папку `ggkadg-pages`.
3. В Finder нажмите Cmd+Shift+. для отображения скрытых файлов. Внутри должна быть папка `.github`.
4. В GitHub откройте Code → Add file → Upload files. Перетащите ВСЁ содержимое `ggkadg-pages`, включая `.github`, в окно загрузки. Не переносите внешнюю папку целиком и не загружайте ZIP как файл.
5. Перед подтверждением убедитесь, что в списке есть `.github/workflows/pages.yml`, `package.json` и `app/page.tsx`. Выберите Commit directly to main → Commit changes. Имеющийся README не затрагивается.
6. Откройте Actions → Publish demo to Pages. Это первая настоящая проверка сборки: в локальной среде нет Node.js. Если сборка красная, не отключайте проверки — сохраните текст ошибки, исключив секреты.
7. После успешной публикации адрес: https://gamgid.github.io/ggkadg/ . До успешного deploy этот адрес не считается рабочим.

Если браузер не загрузил скрытую папку: Add file → Create new file; имя `.github/workflows/pages.yml`, содержимое скопировать из одноимённого файла архива, затем Commit changes. Никаких паролей, токенов или собственных Secrets для этого workflow добавлять не нужно.

## iPhone

После успешной публикации открыть адрес в Safari → Поделиться → На экран «Домой» → Добавить. Если доступен переключатель «Открывать как веб-приложение», включить его. При первой проверке нужны интернет и загрузка приложения. Это веб-приложение, не App Store-сборка.

## Изменения относительно оригинала

- Используется уже имеющийся Next.js в режиме output: export, вместо серверной сборки vinext/Cloudflare. Версии оставшихся зависимостей не обновлялись; pnpm-lock сохраняет исходные разрешённые версии и контрольные суммы. Неиспользуемые записи пакетов в lock оставлены, чтобы не генерировать его заново без pnpm.
- Удалены из списка прямых зависимостей ненужные интеграции хостинга; новые зависимости не добавлены.
- Base path `/ggkadg`, корректные адреса manifest, иконок и service worker.
- Локальная демонстрационная страница профиля доступна только по `/p/demo-profile/`. Серверный поиск по любому ID не поддерживается. Это не обмен данными между устройствами.
- Встроенный профиль заменён на явно тестовый. Изображение og.png, материалы video-review, .git, старые сборки, настройки хостинга, node_modules и архивы не включены.
- Масштабирование страницы пользователем не блокируется.
- Service worker показывает честный офлайн-экран. Полная работа без сети не реализована и не обещается.

## Ограничения

Кнопки-макеты и остальные недостатки исходной версии ещё не исправлены. Профиль хранится в localStorage этого браузера/установленной веб-версии; синхронизации и переноса со старого адреса нет. Не используйте настоящие персональные данные или документы. Публичный исходный код виден всем; вводимые локально данные этот код не отправляет в репозиторий. Разные приложения на том же origin не являются отдельной границей защиты localStorage.

В рабочей среде выполнены только статические проверки пакета. Сборка, проверка интерфейса и установка на iPhone ещё не выполнены. Workflow устанавливает зависимости на временном GitHub runner с отключёнными lifecycle scripts, собирает статические файлы и только после успешной проверки публикует `out/`. Серверного runtime и авторизации нет.
