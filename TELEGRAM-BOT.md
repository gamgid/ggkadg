# Управление режимом 0/1 через Telegram

## Что делает бот

Администратор отправляет боту ID профиля, например `DEMO-57392817`. Бот читает текущую строку `public.profile_visuals` и показывает две кнопки:

- `0 · компактно`;
- `1 · крупно`.

После нажатия бот обновляет `watermark_mode`. Открытое приложение применяет изменение при возврате на экран, получении фокуса или автоматически в течение 30 секунд.

Бот не создаёт строки по неизвестному ID: опечатка не добавит случайный профиль. Команда `/profiles` показывает до 25 существующих профилей. Команда `/users` показывает администратору до 20 последних привязанных пользователей: постоянный ID профиля, имя, `@username` и дату последнего входа. Если отправить постоянный `DEMO-...`, бот также покажет Telegram ID и дату регистрации владельца.

## Безопасность

- Код работает как Supabase Edge Function, а не в публичном GitHub Pages.
- Изменения разрешены только Telegram ID из `TELEGRAM_ADMIN_IDS`.
- Telegram проверяет webhook через `TELEGRAM_WEBHOOK_SECRET`.
- `SUPABASE_SERVICE_ROLE_KEY` используется только внутри Edge Function и не попадает в браузер.
- Публичная RLS-политика приложения остаётся только на чтение.
- Токены и ключи нельзя присылать в чат, добавлять в репозиторий или вставлять в исходники.

## Что понадобится для запуска

1. Создать отдельного бота через официальный BotFather.
2. В Supabase Edge Functions добавить секреты через защищённые поля панели:
   - `TELEGRAM_BOT_TOKEN`;
   - `TELEGRAM_WEBHOOK_SECRET` — случайное значение для проверки webhook;
   - `TELEGRAM_ADMIN_IDS` — разрешённые цифровые Telegram ID через запятую.
3. Опубликовать функцию `telegram-visual-bot` с отключённой JWT-проверкой. Запросы всё равно защищены секретом Telegram.
4. Открыть URL функции с параметром `?setup=webhook`. Функция сама зарегистрирует свой URL
   через Telegram API, взяв токен и webhook-секрет из защищённых переменных Supabase.
   Токен не вводится в URL, командную строку или чат.

Файлы функции:

- `supabase/config.toml`;
- `supabase/functions/telegram-visual-bot/index.ts`.

Публикация функции, создание бота и регистрация webhook являются отдельными внешними действиями. Их следует выполнять только после явного согласования и через защищённый ввод секретов.

## Проверка после запуска

1. Открыть диалог с ботом и отправить `/start`.
2. Отправить существующий ID `DEMO-57392817`.
3. Нажать `0 · компактно` и проверить изменение в приложении.
4. Нажать `1 · крупно` и проверить обратное изменение.
5. Отправить несуществующий ID и убедиться, что бот сообщает об отсутствии строки, не создавая её.
6. Отправить `/users` и убедиться, что данные владельцев видит только администратор.
