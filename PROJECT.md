## Точная диагностика отказа Supabase — 2026-09-29

После публикации исправления без Bearer-заголовка GitHub Actions №75 завершился успешно, но приложение продолжило показывать общий отказ Supabase. Опубликованный исходник уже содержит исправленный запрос, поэтому проблема находится в фактическом ответе API, а прежняя диагностика недостаточно различала причины.

Теперь экран настроек показывает безопасный HTTP-код и код Supabase без URL и значения ключа: отдельно распознаются неверный или несовместимый ключ (`401`), отсутствие прав чтения (`403`), отсутствующая таблица/Data API (`404`, `PGRST205`, `42P01`), ограничение запросов (`429`) и прочие HTTP-ошибки. Следующий шаг — опубликовать обновление и по одной точной строке устранить конфигурационную причину.

## Совместимость с Supabase Publishable key — 2026-09-29

После успешной публикации диагностика показала HTTP-отказ Supabase. Причина: новый Publishable key не является JWT, но запрос дублировал его в `Authorization: Bearer`, поэтому Supabase отклонял обращение как `Invalid JWT`. Запрос исправлен: публичный ключ передаётся только через `apikey`, что совместимо и с новым Publishable key, и со старым anon key. RLS и безопасный режим `1` сохранены. Следующий шаг — опубликовать исправление и подтвердить статус «Підключення: синхронізовано» на iPhone.

## Визуал привязан к человеку — 2026-09-28

Удалённый режим больше не читается из общей строки `app_config/main`. Каждый локальный DEMO-профиль запрашивает собственную строку таблицы `profile_visuals` по стабильному `profile.id`; имя и редактируемые персональные поля на привязку не влияют. При смене ID запрос автоматически повторяется, а отсутствие строки или ошибка сети безопасно оставляют крупную маркировку (`1`).

В настройках показан ID профиля и его текущий режим. `REMOTE-CONFIG.md` содержит SQL новой таблицы, RLS только на анонимное чтение DEMO-строк и пример добавления нескольких людей. Старая строка `app_config/main` не используется, но её удаление не требуется. Публикация и интерактивная проверка на iPhone ещё требуются.

## Цель и платформа

Учебное мобильное веб-приложение на React/TypeScript с Next app router и статическим экспортом для GitHub Pages. Это отдельная DEMO-пародия с вымышленными данными, без подключения к государственным системам.

## Что работает

- Главная карточка «Резерв ID» и переворот к локальному DEMO-QR.
- Оранжевый плюс открывает нижнюю панель действий.
- «Переглянути документ» открывает отдельный прокручиваемый экран с вымышленными данными, возвратом и анимированной строкой статуса.
- «Завантажити PDF» открывает локальный полноэкранный предпросмотр в стиле iOS: заголовок, «Done», счётчик страниц, лист A4, кнопки поиска и системной отправки.
- «Оновити документ» открывает локальное окно подтверждения по референсу; «Оновити» намеренно не выполняет действий, а «Скасувати» закрывает окно.
- Вкладки «Сервіси», «Вакансії» и «Меню», локальные настройки и уведомления.
- Сохранение тестового профиля в localStorage.

## Как проверить

Открыть главный экран, нажать оранжевый плюс и выбрать второй пункт «Завантажити PDF». Должен появиться серый полноэкранный просмотрщик с заголовком «Військово-обліковий документ», кнопкой «Done», индикатором «1 из 1» и белым листом. Проверить раскрытие поиска, системную отправку и закрытие через «Done».

Затем снова открыть меню по оранжевому плюсу и выбрать третий пункт «Оновити документ». Должно появиться центрированное окно подтверждения как на IMG_1628. «Оновити» не должно менять состояние или данные; «Скасувати» должно закрыть окно и вернуть главный экран.

Отдельно выбрать «Переглянути документ» и проверить прежний свайп: панель идёт за пальцем, под ней виден главный экран; короткий жест возвращает панель, длинный или быстрый закрывает её. На QR-стороне оранжевый плюс не показывается.

## Ограничения и следующий шаг

Предпросмотр имитирует внешний вид PDF внутри приложения, но не создаёт и не загружает настоящий файл. В среде нет Node.js/pnpm и браузера, поэтому сборка и интерактивный рендер здесь не выполняются. Для первой загрузки файлов шрифта требуется интернет. Следующий шаг — заменить исходники в репозитории и проверить GitHub Actions и внешний вид нового просмотра на iPhone.
